# 匹配确认三层漏斗实施方案

> 版本：v1.0 | 日期：2026-09-15 | 状态：待实施

## 一、问题陈述

### 1.1 当前现象
匹配确认页（/admin/match）候选项质量差：
- 出现"电箱""配电"等2字碎片候选项
- 同名候选项重复（不同分类路径下同名节点）
- 候选项和单价分析维度脱节

### 1.2 根因分析

| 问题 | 根因 | 影响 |
|---|---|---|
| 候选项无意义碎片 | 候选池取全表所有level（含l5叶子spec字段） | 冒出来"电箱""配电"等子串匹配 |
| 候选项重复 | 不同dict_id但name相同 | 用户分不清该选哪个 |
| 匹配范围太宽 | 从13790个l4节点全表模糊匹配 | 必然命中不相关节点 |
| 和单价分析脱节 | 匹配确认和单价分析用不同维度 | 确认后聚合对不上 |

### 1.3 核心洞察
**清单编码本身就是分类**——030404017079前9位030404017已经表明是"控制设备/配电箱"类。但当前匹配流程完全没用这个信息，从全表13790个节点里碰运气。

---

## 二、方案设计：三层漏斗

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────┐
│  清单项 item_code=030404017079（配电箱）              │
└──────────────────────┬──────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  第一层：清单编码锁定分类范围                          │
│  取前9位 030404017                                   │
│  查 list_material_mapping → cat_l3="配电箱"           │
│  候选池：13790 → 30-50个相关节点                      │
└──────────────────────┬──────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  第二层：分类内分级匹配                                │
│  精确=100 > 包含=90 > 同义词=85 > rapidfuzz≥80=70    │
│  > rapidfuzz≥60=50                                   │
└──────────────────────┬──────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  第三层：展示过滤                                      │
│  只l4级 + 过滤长度<3 + 同名去重 + 最低分≥50 + ≤3个   │
└──────────────────────┬──────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  最终候选项：照明配电箱(95) / 动力配电箱(90) / 防爆配电箱(85) │
└─────────────────────────────────────────────────────┘
```

### 2.2 第一层：清单编码锁定分类范围

**输入**：boq_item.item_code（12位国标清单编码）

**处理流程**：
1. 取item_code前9位作为分类码（如030404017）
2. 查list_material_mapping表：code_prefix=前9位 → cat_l3
3. 有映射：候选池限定在 material_dict WHERE cat_l3=对应分类 AND level='l4'
4. 无映射：回退全表l4节点匹配，标注"未锁定分类"

**数据依赖**：
- list_material_mapping表已有3446条映射（覆盖率84.3%）
- 需要补全剩余15.7%无映射的清单编码

**边界情况**：
- item_code为空：直接走全表匹配
- item_code不足9位：走全表匹配
- 映射表无记录：走全表匹配+标注

### 2.3 第二层：分类内分级匹配

在锁定的分类候选池内，按以下优先级打分：

| 优先级 | 匹配规则 | 分数 | 说明 |
|---|---|---|---|
| 1 | 名称完全等于字典l4名称 | 100 | 精确匹配，无歧义 |
| 2 | 清单项名称包含字典l4名称 | 90 | 如"照明配电箱"包含"配电箱" |
| 3 | 同义词表命中 | 85 | 配电箱↔配电柜↔开关柜等9组 |
| 4 | rapidfuzz partial_ratio ≥ 80 | 70 | 模糊匹配兜底 |
| 5 | rapidfuzz partial_ratio ≥ 60 | 50 | 低置信，仅兜底显示 |

**分数融合**：
- 取各算法最高分，不做加权平均（因为是在分类内匹配，精确匹配应该直接胜出）
- 同名候选项只保留最高分（已实现）

### 2.4 第三层：展示过滤

| 规则 | 阈值 | 原因 |
|---|---|---|
| 只显示l4级节点 | level='l4' | l5是规格叶子，不是材料名称 |
| 过滤名称长度 | ≥3字符 | 消除"电箱""配电"等2字碎片 |
| 同名去重 | 保留最高分 | 避免重复 |
| 最低分阈值 | ≥50 | 低分候选项无参考价值 |
| 最多候选项数 | ≤3 | 避免选择困难 |
| 候选项显示 | 名称+分类路径+分数 | 用户需要知道候选项在字典中的位置 |

## 三、和单价分析联动

### 3.1 数据流向

```
匹配确认页
  ↓ 用户点击"确认为此项"
  ↓ 回填 boq_item.material_dict_id（l4级）
单价分析页
  ↓ 按 material_dict_id 聚合
  ↓ 聚合身份 = cat_l1/cat_l2/cat_l3/名称（分类路径）
  ↓ 价格趋势图、直方图、报价对比按分类路径分组
```

### 3.2 一致性保证
- 匹配确认候选池 = l4级节点
- 单价分析聚合维度 = material_dict_id（l4级）
- 两者用同一把尺子，不会出现"确认成A，分析按B聚合"

## 四、实施步骤

### 步骤1：查映射覆盖率（0.5天）
- 统计list_material_mapping表按清单前9位分组的覆盖率
- 输出：已有映射数/总数/覆盖率，无映射的Top20清单编码

### 步骤2：候选池改造（1天）
- 修改page_services.py的get_pending_matches
- 新增：按item_code前9位查映射，锁定cat_l3范围
- 无映射时回退全表l4节点
- 只取l4级，过滤name长度<3

### 步骤3：分级匹配规则（0.5天）
- 修改score_candidates函数
- 新增：精确=100 > 包含=90 > 同义词=85 > rapidfuzz≥80=70 > rapidfuzz≥60=50
- 同名去重（已实现）

### 步骤4：展示过滤（0.5天）
- 最低分阈值≥50
- 最多3个候选项
- 候选项显示完整分类路径

### 步骤5：无映射回退+标注（0.5天）
- 无映射时走全表匹配
- 候选项旁标注"未锁定分类，建议人工确认"

### 步骤6：验证（0.5天）
- 配电箱类：候选项应该是照明配电箱/动力配电箱/防爆配电箱等
- 电缆类：候选项应该是电力电缆/控制电缆/计算机电缆等
- 钢管类：候选项应该是焊接钢管/镀锌钢管/无缝钢管等
- 阀门类：候选项应该是闸阀/截止阀/球阀等

## 五、验收标准

| 验收项 | 标准 | 验证方法 |
|---|---|---|
| 碎片候选项 | 0个 | 配电箱类不出现"电箱""配电" |
| 同名重复 | 0个 | 同名候选项只出现一次 |
| 候选项数量 | ≤3个/清单项 | 页面截图 |
| 最低分阈值 | <50不显示 | 检查候选项分数 |
| l4级节点 | 100% | 候选池level='l4' |
| 映射锁定 | 有映射时候选池≤50个 | 配电箱类候选池≤50 |
| 单价分析联动 | 确认后material_dict_id是l4级 | DB查询 |

---

## 六、风险与边界

| 风险 | 应对 |
|---|---|
| 映射覆盖率不足（15.7%无映射） | 无映射时回退全表匹配+标注，后续逐步补全 |
| 分类内节点太多（>50个） | 按分数排序取top-3，不全部显示 |
| 分类内节点太少（<5个） | 回退全表匹配，补充候选项 |
| 同义词表不够全 | 人工确认后自动学习，写入同义词表 |
