# 匹配确认与单价分析 · 长期规则（100万+数据量适配）

> 原则：规则现在生效，但实现按数据量分阶段。不提前上重武器，但也不留架构债。

---

## 一、候选项分级规则

| 档位 | 分数 | 触发条件 | 动作 | 闸门 |
|---|---|---|---|---|
| **S级 自动确认** | =100 | 前9位清单码在映射表中存在，且映射材料名在字典l3/l4精确同名 | 直接写库，记审计 operator=system-auto | 映射表版本号变更后，已自动确认的标"待复核" |
| **A级 高置信** | 90-99 | rapidfuzz+TF-IDF融合分≥90 | 进待确认列表，**默认勾选**，支持一键批量确认 | 批量确认前弹确认框，显示将影响N条 |
| **B级 中置信** | 75-89 | 融合分75-89 | 进待确认列表，**默认不勾选**，人工逐条点 | 无 |
| **C级 低置信** | 50-74 | 融合分50-74 | 候选项灰显，排在最后 | 不参与批量确认 |
| **D级 低置信参考** | 0-49（score>0） | 字典无高相似项，但有部分匹配 | **推荐最多3条不同候选**（按 name 去重取前3），红色显示排最后，供人工参考挑选 | 仅全0分（完全无相似）才显示"无候选"，提供①标记为非材料项 ②手动添加到字典 |

**阈值常量（集中在 data/match_score.py）**：
- AUTO_CONFIRM_SCORE = 100
- DEFAULT_CHECK_SCORE = 90
- SHOW_MIN_SCORE = 50
- 改动须同步 pure_tests/ 和文档

## 二、映射表治理规则

1. **唯一权威**：list_material_mapping 是"清单码→材料名"的唯一权威源，代码不做猜
2. **改动留痕**：任何映射表改动必须记审计（谁改的、从什么改成什么、为什么）
3. **版本号机制**：映射表加 version 字段，每次改动 version+1；已自动确认的数据带 mapping_version，version 不匹配时标"待复核"
4. **不允许碎片映射**：material_name 长度≥3，且必须在字典l3/l4中真实存在（孤儿映射禁止入库）
5. **生成方式**：
   - 批量初始化：用2013/2024清单规范表 + 人工校准（当前阶段）
   - 增量更新：人工确认一条→自动写映射表（反馈闭环）
   - 禁止：用rapidfuzz全自动生成映射表（子串误匹配教训）

## 三、100万+性能规则

| 指标 | 规则 |
|---|---|
| 候选池 | 只取l3+l4（~1.4万条），不取l5（14万条会拖慢） |
| 实时打分 | 单次请求 ≤200ms；超过则触发预计算 |
| 预计算 | 导入完成后，异步为所有待确认项算好候选，写缓存表 match_candidate_cache |
| 匹配确认页 | 分页50条，不一次性拉全量；前端AbortController取消上一次请求 |
| 字典搜索 | pg_trgm GIN索引已建；模糊查询走PG similarity()，不在Python端全表扫 |
| 单价分析 | 聚合查询走物化视图或预聚合表，不实时GROUP BY百万行 |

## 四、数据安全规则（对齐AGENTS.md S1-S9）

1. **自动确认不碰B类字段**：只写 material_dict_id / match_key / aggregate_id / match_key_source，B类（材质/规格/单价）仍走人工
2. **可回滚**：审计日志完整记录（谁/什么时候/从什么改成什么），提供"撤销确认"按钮
3. **fail-closed**：候选池为空、映射表查不到、字典无此材料 → 不自动猜，进人工队列
4. **硬删闸门**：材料字典删除走四道锁（admin + 名称确认 + 30天宽限 + CSV快照）
5. **源文件只读**：导入用的原始Excel永不修改（S1）

---

## 五、反馈闭环规则

1. **人工确认一条**：
   - 更新 boq_item.material_dict_id
   - 自动写 list_material_mapping（如果该清单码还没映射）
   - 自动写 material_dict.synonyms（学习同义词）
2. **人工忽略一条**：记 audit，不写映射
3. **手动添加新材料**：
   - 写入 material_dict（l4级，归到正确l3父节点）
   - 同时写 list_material_mapping
   - 下次同类直接S级自动确认
4. **纠错**：用户点"撤销"后，删除对应映射表行，退回待确认

## 七、不做什么（明确边界）

1. ❌ 不上l5规格匹配（单价分析按l4材料名聚合已够）
2. ❌ 不自动分流"措施项目"（让人主动标记，不靠章节号猜）
3. ❌ 不上90分以下自动确认（误确认污染不可逆）
4. ❌ 不用算法自动生成映射表（子串误匹配教训）
5. ❌ 不做实时全表rapidfuzz（10万+时必崩，走预计算）
