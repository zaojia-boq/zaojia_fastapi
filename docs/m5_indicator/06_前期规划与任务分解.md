# 前期规划与任务分解

> M5 自动指标生成 · WBS 任务分解、依赖关系、风险点、里程碑
> 目标：4-6 周完成 M5 核心功能，最大化复用现有资产

---

## 一、项目目标

### 1.1 核心目标
从已入库的工程量清单数据，一键生成符合 DB11/T1711-2019 标准的 E 经济指标 / Q 工程量指标 / D 单价指标全套成果，替代人工汇总，提升指标编制效率。

### 1.2 成功标准
- [ ] V6 编码字典入库（E/Q/D 三套，93 个分部工程级编码）
- [ ] 编码匹配准确率 ≥ 90%（自动确认），人工复核可回填
- [ ] E/Q/D 指标计算正确，精度符合 DB11 3.0.4
- [ ] Q×D≈E 偏差校验，三级判定（合格/注意/异常）
- [ ] 成果导出符合 DB11 标准表格格式（6 类标准 Sheet）
- [ ] 与豆包对话示例（云溪华庭 1# 楼 496 条清单）结果一致
- [ ] 全量测试零失败（pure_tests + FastAPI 集成测试）
- [ ] 安全用例通过（审计记录、权限控制、原始数据只读）

### 1.3 非目标（本期不做）
- 多项目指标对比（远期扩展）
- 指标趋势分析（远期扩展）
- 行业基准对比（远期扩展）
- BIM 集成（远期扩展）
- 移动端适配（远期扩展）

### 2.2 M5.1 V6 编码字典入库（3-5 天）

#### 任务内容
1. 整理完整的 E/Q/D 编码字典（建筑 21 + 装饰 20 + 安装 56 = 97 条 × 3 类 = 291 条编码）
2. 编写 `data/v6_code_dict.py` 纯函数（零框架依赖，可 pure_tests 测试）
3. 编写 `models/v6_code.py` 编码表（支持用户扩展/版本化管理）
4. 编写编码管理 API（查询/新增/修改/版本管理）
5. Alembic 迁移脚本

#### 交付物
- `data/v6_code_dict.py`：编码字典纯函数
- `app/models/v6_code.py`：编码表模型
- `app/api/v6_code_api.py`：编码管理 API
- `alembic/versions/xxx_add_v6_code_table.py`：迁移脚本
- `pure_tests/test_v6_code_dict.py`：编码字典测试

#### 验收判据
- 编码字典可查询，E/Q/D 编码分离
- 同名称分部编码不同（名称码共享，指标分类码不同）
- 编码支持版本化管理
- pure_tests 全绿

#### 风险点
- 编码字典完整性：需确保 97 条分部编码完整无遗漏
- 编码准确性：需与湘标 2.0 核对，确保编码规则正确

## 五、风险点与应对

| 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|
| V6 编码字典不完整/不准确 | 中 | 高 | 与湘标 2.0 核对，分专业分批入库，人工复核 |
| 编码匹配准确率不足 | 中 | 高 | 复用 M3 三算法融合 + 学习引擎，人工复核反馈学习，持续优化 |
| 多计量单位处理复杂 | 中 | 中 | 取合价占比最大的单位汇总，其他单位单独列示，备注说明 |
| DB11 标准表格格式复杂 | 中 | 中 | 参考标准模板，分 Sheet 开发，逐个验证格式 |
| 大数据量性能问题 | 低 | 中 | 异步计算 + 缓存 + 分页查询，10 万条数据目标 < 5 分钟 |
| 与现有系统集成冲突 | 低 | 中 | 新增模型/服务/API，不修改现有代码，通过外键关联 |
| 建筑面积 S 缺失 | 低 | 高 | 必填校验，S=0 报错，从 import_batch 自动填充 |
