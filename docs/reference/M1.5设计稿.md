# M1.5 设计稿 · 深空科技设计系统（Odoo 原生观感改造）

> 版本：**v1（初稿）** · 日期：2026-09-01
> 上游文档：`架构设计.md` **v6.3 §9**、`产品设计文档.md` **v6.2 §9**、`M1模块设计.md` **v3.3 §12**
> 范围边界：**仅设计，不写代码、不安装 Odoo/PostgreSQL、不装 Python 依赖、不编译 SCSS**
> 衔接：M0 装环境 → M1 数据层 → **M1.5 设计系统（本稿）** → M2 导入向导/搜索/导出 → M3 分析/匹配向导

## 1. M1.5 定位（做什么 / 不做什么）

| 做 | 不做 |
|---|---|
| 给 Odoo 现有控件「穿衣服」——色彩、圆角、字体、阴影、留白、动效 | 不动模型字段、视图结构、权限、业务逻辑 |
| 用 CSS 变量（token）统一观感，后续换肤靠改 token 表 | 不内嵌字体文件（SF Pro 用系统字体栈降级） |
| 写 OWL 自定义组件（如 KPI 卡片） | 不魔改 Odoo 原生 OWL 组件 |
| 浅色 + 深色两套 token，**组件零改动** | 不改 Odoo 核心一行 |

**核心取舍（已在架构 §9.1 写明，本稿不再重复论证）：要 深空科技视觉语言，不要 深空科技参考案例信息密度。留白压缩到 0.3 倍，列表行高 ≥40px，一屏 ≥15 行。**

> **M1→M1.5 铁律**：M1 的视图必须干净——无内联 style、无自定义 class、标准 `<group>` 分组。否则 M1.5 要先清理脏结构再改观感，返工风险翻倍（详见 §8）。

### 3.4 **禁止裸值铁律**

**所有组件样式只允许引用 token，禁止在任何 scss 中出现上述 15 个 token 值的字面量**（`!important` 覆盖除外，须在注释中写清原因）。原因：
1. 换肤靠改 token 表，裸值会绕过 token 体系；
2. 深色模式只覆盖 token 值，裸值会在深色下失效或翻车；
3. 升级后核对清单「无裸值颜色」直接判定违规。

> **例外**：`overrides/` 下的文件可酌情使用裸值，但必须在首行注释写明「此规则无法通过 token 覆盖，原因：xxx」。

## 4. 落地路径（四条铁律的执行细节）

### 4.1 铁律①：不修改 Odoo 核心

**每次改完 scss/js/xml 后必跑**（AGENTS.md 已登记命令）：

```bash
cd <odoo-source>/odoo/addons && git status --porcelain    # 必须为空
grep -rn "zaojia" <odoo-source>/odoo/addons/web/ | head   # 必须为零结果
```

若核心目录有改动，**立即 revert，绝不妥协**。

### 4.2 铁律②：不复制 参考案例商业资产

不下载、不复现、不使用任何 受保护的参考案例资产（图标、字体文件、动效参考视频）。所有图标用 Odoo 自带的 `fa-*`（Font Awesome）或 Material Icons。

### 4.3 铁律③：卸载模块后恢复默认观感

`__manifest__.py` 的 `assets` 字典只挂本模块的 scss/js/xml，**不挂任何系统级 bundle 的 patch**。Odoo 卸载时，`assets` 里挂的文件自动从加载列表移除，浏览器不再加载，观感回到 Odoo 默认。

**验证方法**：模块卸载 → 刷新 → 截图与 Odoo 默认基线对比。

### 4.4 铁律④：bundle 命名已实测确认（M0 STEP5）

M0 已在 Odoo 19.0 源码实测确认三个 bundle 的**实际名称**，M1.5 直接引用：

| 用途 | bundle 名 |
|---|---|
| 注入目标（tokens/components） | `web.assets_backend` |
| primary variables（主色/圆角/字号） | `web._assets_primary_variables` |
| 深色模式 | `web.assets_backend_lazy_dark` |

> 若后续 Odoo 升级导致命名变化，再回源码 `grep` 核对（下方命令保留备用）。动手前在 Odoo 19 源码中执行：

```bash
grep -rn "web.assets_backend" <odoo-source>/odoo/addons/web/
grep -rn "primary.*variables\|brand.*primary" <odoo-source>/odoo/addons/web/  # 找 primary variables bundle 名
grep -rn "dark.*mode\|o-dark-mode" <odoo-source>/odoo/addons/web/              # 找深色 bundle 名
```

上表即实测结果，M1.5 写 `__manifest__.py` 的 `assets` 字典时直接引用。

> **额外验证项**（装完环境后顺手跑）：
> ```bash
> grep -rn '"assets"' <odoo-source>/odoo/addons/web/static/src/  # 找 web 模块的 assets 定义
> grep -rn "o-dark-mode\|dark_theme" <odoo-source>/odoo/addons/web/static/  # 确认深色 class 名
> ```
> 若上述 grep 找到新的 bundle 名或深色 class 名，以源码为准更新本文档。

## 5. SCSS 文件职责分工

### 5.1 `primary_variables.scss`（挂 `web._assets_primary_variables`）

**目标**：覆盖 Odoo/Bootstrap 的默认变量，让原生控件自动跟着变。

| 变量（需 grep 确认） | 覆盖目标 | 示例值 |
|---|---|---|
| `$o-brand-primary` | Odoo 主色 | `var(--zj-accent)` |
| `$o-brand-secondary` | 次级色 | `var(--zj-text-2)` |
| `$input-border-color` | 输入框边框 | `var(--zj-separator)` |
| `$input-border-radius` | 输入框圆角 | `var(--zj-radius-md)` |
| `$badge-border-radius` | 标签圆角 | `var(--zj-radius-sm)` |
| `$dropdown-border-radius` | 下拉圆角 | `var(--zj-radius-md)` |
| `$font-family-base` | 基础字体 | `var(--zj-font-family)` |
| `$font-size-base` | 基础字号 | `14px` |

> **⚠️ 重要**：变量名必须以 `grep` 源码确认的结果为准，本文档列的是**常见命名惯例**，非 Odoo 19 的权威名称。

### 5.2 `tokens.scss`（挂 `web.assets_backend`）

**目标**：定义所有 `--zj-*` CSS 变量，作为单一事实来源。

```scss
// 此文件仅定义变量，无任何选择器
:root {
  --zj-accent: #4D7CFE;   // 主色深空蓝（ADR-006 定夺；v1.7 体检修正：原残留 #0071E3）
  // ... 其余 token 见 §3.1-3.3
}

// dark-first：深色为全局基调，accent 浅深同值，**不设 .o_dark_mode 覆盖**
// （实测 tokens.scss 暗色段仅覆盖 bg-hover/separator 等差异项；原稿 #0A84FF 暗色主色从未实现，v1.7 体检删除）
```

### 5.3 `components/*.scss`（挂 `web.assets_backend`）

**目标**：针对每个组件，用 token + 选择器实现 深空科技化处理。每个文件职责单一：

| 文件 | 目标组件 | 关键处理 |
|---|---|---|
| `navigation.scss` | 顶部导航 | 毛玻璃 `backdrop-filter`、高度 48px、1px 分隔线 |
| `list.scss` | 列表视图 | **斑马纹回归**（偶数行 `--zj-bg-zebra`，M2.5-UI P1 反转，见 §6.2）、行高 44px、悬浮态 `--zj-accent-faint`、表头 `--zj-bg-raise`、圆角容器 |
| `form.scss` | 表单视图 | 卡片化分组（`--zj-bg-subtle` 底 + 1px 分隔 + 圆角）、label 12px 次级色 |
| `search.scss` | 搜索视图 | 筛选条件变胶囊 chip（圆角 + 移除按钮 ×） |
| `button.scss` | 按钮 | 主操作：实心主色胶囊；次操作：无边框文字；危险操作：红色文字 |
| `status_badge.scss` | 状态标签 | 小圆点 + 文字，用 token 着色 |
| `empty_state.scss` | 空状态 | 居中说明 + 引导按钮，隐藏空表头 |
| `card.scss` | 卡片工作台（M2.5-UI P1 登记） | 表单 sheet 卡面 `--zj-card` / 双层阴影 / 笔记本页签 / 弹窗 / `.zj_dropzone` 上传区 |
| `overrides/navigation_layout.scss` | （备用） | 仅当无法通过 token 覆盖时使用，注释说明原因 |

> **M2.5-UI P1 登记（2026-09-04）**：新增 `scripts/check_assets.py`——SCSS/QWeb 资产强制编译门禁（venv python 运行、关 sandbox；判据 assets_backend + lazy_dark PASS，`web._assets_primary_variables` 的 `no mixin named o-hover-text-color` 为 Odoo 19 既有现象仅记录）。

### 5.4 `dark_tokens.scss`（挂 `web.assets_backend_lazy_dark`）

**目标**：只覆盖 `:root` / `.o_dark_mode` 下的 token 值，**组件文件零改动**。
（Odoo 19 实测深色 class 为 `.o_dark_mode`；`tokens.scss` 同时 emit `.o_dark_theme` 兼容旧文档。）

```scss
// 此文件仅覆盖 token，不写任何选择器
.o_dark_mode {
  --zj-bg: #000000;
  // ... 见 §3.1 深色列
}
```

## 6. 组件规范落地细节（对照 `架构设计.md` §9.5）

### 6.1 顶部导航

| 导航栏高度 | 48 px | 工业软件常见导航标准高度 |
| 导航栏毛玻璃 blur | 20 px | `blur(20px)`，不过度模糊影响可读性 |
| 导航栏毛玻璃 saturate | 180% | `saturate(180%)`，增强色彩但不溢出 |
| 卡片圆角 | 12 px | `--zj-radius-md`，平衡现代感与正式感 |
| 大卡片圆角 | 18 px | `--zj-radius-lg`，用于 KPI 卡片等主视觉组件 |
| 按钮胶囊圆角 | 980 px | `--zj-radius-pill`，深空科技标志性胶囊形状 |
| 列表行高最小值 | 40 px | 硬指标，一屏 ≥ 15 行（1440×900 分辨率） |
| 动效时长（快） | 160 ms | `--zj-dur-fast`，悬浮/选中态过渡 |
| 动效时长（标准） | 280 ms | `--zj-dur`，页面切换/展开过渡 |
| 动效曲线 | `cubic-bezier(.25,.1,.25,1)` | `--zj-ease`，深空科技标志性 ease-out 曲线 |
| 导航栏毛玻璃禁用于 | 表格行、滚动区域 | 大面积使用会导致掉帧（性能约束） |

### 6.2 列表视图

- **去斑马纹**：覆盖 `$table-striped-bg` 为 transparent
- **行高**：`min-height: 40px`（不设置 max-height，行内内容撑开）
- **悬浮态**：`background: var(--zj-bg-hover)` + `transition: background var(--zj-dur-fast) var(--zj-ease)`
- **容器**：圆角 12px + `box-shadow: var(--zj-shadow-1)`
- **表头**：12px、`--zj-text-3`（次级色）
- **保留**：排序/分组/分页/导出/行内编辑全部不变

> **变更注记（2026-09-04 M2.5-UI P1）**：斑马纹回归（偶数行 `--zj-bg-zebra`，demo `--tbl-zebra`），上方原「去斑马纹」决策**作废**；行高硬指标由 40px 升至 44px（demo `--row-h`，仍满足 ≥40px 与一屏 ≥15 行）。

### 6.3 表单视图

- **卡片化分组**：每组 `<group>` 渲染为白底卡片，圆角 12px，1px 分隔线 `--zj-separator`
- **Label**：12px、`--zj-text-3`，显示在字段上方（不在左侧）
- **输入框**：聚焦时主色描边 `var(--zj-accent)`，不用粗边框
- **禁用**：`appearance: none`，用 token 统一样式
- **保留**：字段布局引擎、widget（如 month 选择器）

### 6.4 搜索视图

- **筛选条件**：渲染为胶囊 chip（圆角 980px / 内边距 4px 8px），配 `×` 移除按钮
- **搜索框**：圆角 12px，`--zj-separator` 边框
- **保留**：组合筛选、收藏过滤器、高级搜索语法

### 6.5 按钮

| 类型 | 样式 |
|---|---|
| 主操作 | 实心 `var(--zj-accent)` 背景，圆角 980px，白色文字 |
| 次操作 | 透明底 + `--zj-card-border` 描边 + `--zj-text-2` 文字，悬浮转 `--zj-accent-soft` 底与 `--zj-accent` 文字 |
| 危险操作 | 红色文字 `var(--zj-danger)`，无背景，悬浮加红底 |

- **禁用**：`opacity: 0.5`，`cursor: not-allowed`
- **保留**：事件绑定、权限控制

> **变更注记（2026-09-04 M2.5-UI P1）**：主按钮悬浮新增「提亮 + `translateY(-1px)` + `--zj-elev-2` 发光」（demo `.btn-primary:hover`）；次按钮由「无边框文字式」改为**描边式**（demo `.btn-sec`），上方表格已同步。

### 6.6 KPI 卡片（单价分析页顶部）

- **自定义 OWL 组件**：`static/src/js/components/kpi_card.js` + `static/src/xml/templates.xml`
- **结构**：大数字（28px / 600）、次级说明文字（12px / `--zj-text-3`）、圆角 18px 卡片、`var(--zj-shadow-2)` 阴影
- **数据源**：走 Odoo 原生聚合（`read_group`）或读组，不从前端二次计算

### 6.7 导入向导

- **步骤条**：顶部 4 步（上传 → 解析 → 预览 → 确认）

## 8. M1→M1.5 衔接清单（M1 必须满足的约束）

M1 写的视图 XML 是 M1.5 的素材。M1 未达标，M1.5 会被自己的脏结构绊倒。

| M1 约束 | 违反后果 | 检查方式 |
|---|---|---|
| 视图 XML **不写内联 style** | M1.5 要先清理再覆盖，样式冲突 | `grep -rn 'style=' *.xml` |
| 视图 XML **不加自定义 class** | 同左；且 M1.5 的选择器可能误伤其他模块 | `grep -rn 'class="[^o_]' *.xml` |
| form 使用**标准 `<group>` 分组** | 卡片化依赖规整分组，嵌套过深会错位 | 人工 review 视图 XML |
| tree 列用 `optional="hide"` 控制密度 | 塞满列会破坏一屏 ≥15 行硬指标 | 人工 review tree 视图 |
| 数值列统一**右对齐** | 单价上下比对是核心动作，深空科技风格也保留 | tree 列 `align="right"` |
| 不引入第三方 UI 依赖（jQuery 插件等） | 升级即崩 | `grep -rn 'jquery\|bootstrap' *.xml` |

> **M1 完成定义包含**：视图 XML 干净（AGENTS.md §测试命令已涵盖此项）。M1.5 开始前再过一次以上检查。
