## 3. 导入向导（核心，P0）

### 3.1 流转时序

```
用户上传 Excel（Step 1）
       ↓
import_service.parse(file)  ← M1 服务，只读打开 + 解析
       ↓
Step 2 预览：展示四项计数 + 异常行列表（M1 服务返回 ParsedResult）
       ↓
用户勾选 data_source_type（强制选择，不得预填）← M1.5 步骤条样式
       ↓
用户点击「执行入库」（Step 3）
       ↓
upsert_service.run(parsed_result, data_source_type)  ← M1 §8.6 时序
   ① 归档幂等先行（复制原始文件到归档目录）
   ② 分层 Upsert（A 类字段更新，B 类人工标注永不覆盖，孤儿行打标 orphaned=True）
   ③ 固化校验和（checksum_count / checksum_total / checksum_hash）
       ↓
Step 4 结果页：展示「新增 N / 更新 M / 孤儿待确认 K / 保留人工标注 X」+ 校验和比对结果
```

> **【v6.6 智能体就绪】** 本向导是 `import_service`（Service 层，架构 §19）的**一个入口**，不是唯一入口。`import_service.preview()` / `commit()` 接受**文件引用**（`file_id`=批次 `biz_id` / `file_path`=受控归档路径 `archive_path` / `file_hash`）即可触发解析与入库——未来智能体持 `file_hash` 或 `archive_path` 即能导入，**无需模拟浏览器上传控件**。向导只负责把 Service 返回的结构化 `ParsedResult` / 计数信封渲染成步骤条 UI。

**关键约束**
- **预览阶段绝不写库**（`upsert_service` 不调用，仅 `import_service.parse` 执行）
- `data_source_type` 未选 → 「执行入库」按钮禁用；模型层 `completed` 默认值仅作兜底（架构 §4.8）
- **单批失败隔离**：单行解析异常绝不中断整批（M1 §8.3）
- **归档时机**：执行入库时，`upsert_service.run()` **内部先归档（幂等，不在 PG 事务内）再写库（事务内）**——与 M1 §8.5/§8.6 一致。**预览阶段不调用归档**。

### 3.2 Wizard 模型定义

```python
# wizards/import_wizard.py
class ImportWizard(models.TransientModel):
    _name = 'zaojia.import.wizard'
    _description = '清单导入向导'

    file = Binary('Excel 文件')
    filename = Char('文件名')
    parsed_preview = Json('预览结果（来自 import_service.parse）')
    data_source_type = Selection([
        ('completed', '已完工程（计入历史均价）'),
        ('control_price', '控制价（基准价，不进入均价统计）'),
        ('bid_price', '投标报价（参考用）'),
        ('pending_review', '待审批次（不计入历史均价）'),
        ('info_price', '信息价（参考价，不进入均价统计）'),
    ], required=True, help='【架构 §4.8】必须显式选择，未选阻断入库；模型层 completed 默认仅作兜底')
    confirm_message = Text('二次确认提示')  # 动态生成，含风险警告
```

> `parsed_preview` 存 `import_service.parse()` 返回的 `ParsedResult`（JSON），**不写库**——只是向导状态暂存，用于渲染预览页。

### 3.3 步骤条 QWeb 模板

复用 M1.5 预置的 `static/src/xml/import_wizard_steps.xml`，四步：

| Step | 名称 | 完成条件 |
|---|---|---|
| 1 | 上传文件 | 文件校验通过（格式/大小/超限） |
| 2 | 解析预览 | `import_service.parse()` 返回非空 ParsedResult |
| 3 | 确认入库 | `data_source_type` 已选 + 用户点击确认 |
| 4 | 入库结果 | `upsert_service.run()` 执行完毕，展示四项计数 |

**步骤条样式**：M1.5 token `--zj-accent` 进度色，当前步高亮，已完成步显示 ✓，当前步可回退（Step 1→2 可改文件重传），Step 3→4 不可逆。

### 3.4 预览计数逻辑（关键）

预览页展示的四项计数（新增 N / 更新 M / 孤儿 K / 保留 X）**不是来自 `upsert_service.run()`**（预览不写库），而是来自 **`upsert_service.preview_mode()`**——一个只计算不写库的模拟方法：

```python
preview_result = upsert_service.preview_mode(parsed_result)
# 返回 {created, updated, orphaned, preserved_manual}
# 与 run() 返回结构相同，但不写库、不归档
```

**为什么需要 preview_mode()**：
1. 用户需要在确认入库前知道"这次导入会改变多少行"
2. 预览不写库，但需要预计算孤儿行（需查数据库中已有记录）
3. preview_mode() 与 run() 使用相同的匹配逻辑，确保预览计数与实际入库计数一致

**预览页展示**：
- 四项计数卡片（M1.5 深空科技风格）
- 异常行列表（warning/error 分类，用 `--zj-warning` / `--zj-danger` token）
- 「执行入库」按钮（`data_source_type` 未选时 disabled）

> **⚠️ 重要**：预览阶段**不调用归档服务**，不写任何库表。只有用户点击「执行入库」后，才按 M1 §8.6 时序执行：归档 → Upsert → 固化校验和。

**上方：四项计数卡（深空科技风格卡片）**

| 计数 | 含义 | 数据来源 |
|---|---|---|
| 新增 N | 新文件首次导入的行数 | `upsert_service.run()` 返回的 `created` |
| 更新 M | 同名同规格行 A 类字段更新数 | `upsert_service.run()` 返回的 `updated` |
| 孤儿待确认 K | 原批次有、本次没有的行数 | `upsert_service.run()` 返回的 `orphaned` |
| 保留人工标注 X | B 类字段未被覆盖的行数 | `upsert_service.run()` 返回的 `preserved_manual` |

**下方：异常行预览表（表格）**

| 列 | 说明 | 样式 |
|---|---|---|
| 行号 | Excel 物理行号（= `sequence`） | — |
| 原因 | warning / error 分类 | `--zj-warning` / `--zj-danger` 背景 |
| 原始值 | 解析失败的原始单元格内容 | 截断 50 字符 |
| 建议 | 人工处理建议 | — |

**异常行配色**：M1.5 `status_badge.scss` + `list.scss` 的 `--zj-warning`/`--zj-danger` token，**禁止裸值**。

**底部操作**
- 「取消」：丢弃本次上传，返回列表
- 「执行入库」（禁用态）：`data_source_type` 未选时 disabled；选中后 enabled，点击触发 Step 3 → `upsert_service.run()`

### 3.5 入库后结果页

- 四项计数（可展开看明细）
- **校验和比对结果**：`checksum_count` / `checksum_total` 与 Excel 合计行自动比对，不一致则红色高亮告警（M1 §4.10）
- 「返回查询列表」按钮（跳转 boq_item tree view）
- 审计日志写入：`audit_log.create({..., action='import', batch_id=...})`

### 3.6 向导状态持久化（备选方案）

**问题**：TransientModel 在浏览器刷新后状态丢失，用户需重新上传解析（< 3s，可接受）。

**备选优化**：若用户反馈刷新丢失体验差，可考虑：
- 将 `parsed_preview` JSON 缓存到 `session.storage`（前端本地），刷新后自动恢复预览
- 或使用 Odoo `ir.session` 存储临时状态（需额外开发）

**当前决策**：M2 不做持久化，刷新后重新 parse（轻量，< 3s）。若后续迭代需要，再补。

## 4. 搜索视图（查询检索，P0）

> **【v6.6 智能体就绪】** 搜索视图的 filter / groupby 是 `boq_query_service.search(params)`（Service 层，架构 §19）的**界面映射**。该 Service 返回**结构化结果信封**（含 `data` / `total` / `warnings` / `trace_id` + 每行 `source_location`），Odoo 视图只做渲染；未来 `/api/v1/boq/search` 直接复用同一 Service，无需为页面另写逻辑。

### 4.1 搜索框 + Chip 筛选

复用 M1.5 `search.scss` 的 chip 样式。搜索视图包含两类条件：

**文本搜索框（Odoo 原生 search）**
- 搜索字段：`item_name` / `std_name` / `item_code` / `project_name`（全文模糊）

**Chip 筛选器（Odoo 原生 filter 定义）**

| Filter 名 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 项目编码 | `item_code` | 字符 | 支持前缀匹配 |
| 项目名称 | `item_name` | 字符 | 模糊匹配 |
| 标准化名称 | `std_name` | 字符 | 模糊匹配 |
| 计量单位 | `unit` | 字符 | 精确匹配（已归一化） |
| 工程名称 | `project_name` | 字符 | 模糊匹配 |
| 省份 | `province` | 字符 | 精确匹配 |
| 价格期 | `price_period` | 日期（月份选择器，`options="{'max_precision':'months'}"`，只选年月不选日） | 区间选择 |
| 数据性质 | `data_source_type` | 选择 | 单选 chip（5 选 1：completed / control_price / bid_price / pending_review / info_price） |
| 异常标记 | `anomaly_flag` | 布尔 | 仅显示异常行 |
| 已关联字典 | `material_dict_id` | 关系 | 是否已标准化 |

### 4.2 GroupBy 分组

| GroupBy | 说明 | 用途 |
|---|---|---|
| 工程名称 | 按工程聚合 | 场景 1：报价查某工程全量清单 |

## 5. 批次管理（P0）

> **【v6.6 智能体就绪】** 批次列表/详情/软删/还原按钮均经 `batch_service`（Service 层，架构 §19）与 `import_batch` 模型交互；`batch_service.list()` / `get()` 返回结构化结果，未来 `/api/v1/batches` 与 `/api/v1/batches/{id}` 直接复用。

### 5.1 批次列表视图

树形视图 + 操作按钮。列表字段：

| 字段 | 说明 |
|---|---|
| 批次名 | `name`（自动生成为日期+序号） |
| 源文件 | `source_file`（带超链接打开归档文件） |
| 归档路径 | `archive_path`（只读，可复制） |
| 行数 | `row_count` |
| 跳过的行数 | `skipped_count` |
| 数据性质 | `data_source_type` badge |
| 省份 | `province` |
| 价格期 | `price_period` |
| 导入时间 | `imported_at` |
| 操作人 | `operator` |
| 校验和 | `checksum_count` / `checksum_total`（不一致时红色） |
| active | 是否激活（回收站标记） |

**操作按钮**
- 「重新导入」：打开向导，预填 `file_hash` 提示是否覆盖
- 「查看详情」：跳转到该批次的 boq_item 列表（filter = `import_batch_id`）
- 「软删除」：标记 `active=False`，进回收站
- 「硬删除」：需二次确认 + 输入批次名 + 自动导出快照（架构 §4.7）

### 5.2 回收站视图

新增 one2many 反向视图，展示所有 `active=False` 的批次 + 其关联的 boq_item。

- 回收站批次保留 **30 天**（可配置），30 天后允许硬删除
- 回收站内批次支持「一键还原」：`active=True` + 关联 boq_item 一并还原
- 硬删除闸门：管理员权限 + 二次确认 + 输入批次名 + **自动导出全量 CSV 快照到归档目录**（架构 §4.7 硬删除闸门）

### 5.3 人工资产闸门

若待删批次含 B 类数据（`std_name`/`std_spec`/`material_dict_id` 非空），**强制先展示「将丢失 X 条人工标注」并要求导出快照**，否则不允许继续删除。

## 6. 导出（P0）

### 6.1 导出范围

- **默认导出**：当前筛选结果集（非全表），含原始字段 + 标准化字段 + 溯源字段
- **导出字段**（默认勾选，可自定义）：
  - 原始字段：`item_code` / `item_name` / `item_feature` / `unit` / `quantity` / `unit_rate` / `total_amount`
  - 标准化字段：`std_name` / `std_spec` / `material_dict_id`
  - 溯源字段：`import_batch_id` / `archive_path` / `data_source_type` / `province` / `price_period`
  - **默认不含**：`checksum_*` 等内部字段（可手动勾选）

### 6.2 导出闸门

| 规则 | 做法 |
|---|---|
| 导出留痕 | 每次导出写 `audit_log`（谁、何时、筛选条件、行数、导出字段） |
| 大批量闸门 | 单次 > 1000 行需二次确认，提示「本次导出含商业敏感单价」 |
| 文件格式 | Excel (.xlsx) 默认；CSV 备选（大数据量时更快） |

### 6.3 实现方式

复用 Odoo 原生列表导出（`ir.actions.act_window` → export 按钮），**无需自定义控制器**。但需在导出前拦截写入 `audit_log`（M1 `audit_log` 模型已就绪，M2 在向导层显式写日志）。
