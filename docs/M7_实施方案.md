## 二、关键设计决策（评审修订后新增）

### 2.1 指标字段分层：A 类，可重建，不进 B 类保护（修复 P0-5）

新写的 `e_code/q_code/d_code/indicator_level` 是**从清单名称+编码可重新计算的派生物**，定为 **A 类字段**：
- 重跑指标计算时允许覆盖
- 不进 `field_spec.py` 的 B_FIELDS 列表
- 不需要显式 reason
- 但写入仍走审计中间件（谁在什么时候跑的指标计算，有日志）

### 2.2 两层聚合键对账规则（修复 P0-4）

| 层 | 聚合键 | 回答的问题 | 关系 |
|---|---|---|---|
| 条目级单价分析 | `aggregate_id`（regex:大类:规格） | "YJY-5*10 历史多少钱" | 5 大类正则，按规格分桶 |
| 工程级指标分析 | `e_code` / `q_code` | "这个工程钢筋含量多少" | V6 编码，按分部/分类分桶 |

**对账规则**：两层独立，不要求同一条数据在两边分桶一致。钢筋Φ16 在单价分析页叫"钢筋:Φ16"，在指标页叫"5AQGJJLT 钢筋及螺栓铁件"——这是两个维度，页面导航明确分开，不强行映射。

### 2.3 E 级回退逻辑写死（修复 P0-2）

```
匹配优先级（从上到下，命中即停）：
  1. gb_code_9 前4位命中 qd_dict.gb_prefix → QD 分类级
  2. item_name 分词后命中 qd_dict.keywords（子串匹配加词边界）→ QD 分类级
  3. 以上都不命中 → E 级回退：用 gb_code_9 前4位查 e_dict.gb_prefix，
     取到 e_code 后，q_code=d_code=e_code（分部级回退，不分 QD 子分类）
  4. 连 e_dict 都没命中 → unmatched，indicator_level='unmatched'
```

**预期覆盖率**（云溪华庭 496 条基线）：
- QD 分类级：~70%（431/496，与 Excel 版一致）
- E 级回退：~15%（~65/496）
- unmatched：~15%（主要是市政/园林/特殊项，2024 清单无对应分类）

### 2.4 建筑面积口径（修复 P0-3）

| 场景 | 处理 |
|---|---|
| 新导入工程 | 导入向导必填建筑面积，校验 >0 且 <100 万 |
| 历史 2655 条已导入数据 | **不算单方指标**，e_summary 留空，指标页标注"建筑面积未录入，仅展示合价不展示单方" |
| 多栋楼/地下室 | 一个 import_batch = 一栋楼，建筑面积填该栋；多栋楼分多次导入 |
| 跨工程对比 | 必须选≥2 个有 building_area 的工程；无 building_area 的工程不进对比下拉 |

### 2.5 性能与降级（修复 P0-1 + P1-6）

| 项 | 设计 |
|---|---|
| qd_dict 加载 | 启动时一次性加载到内存（182 条，<100KB），不每次查 DB |
| 匹配算法 | 关键词预编译成正则字典，item_name 一次扫描命中多个候选，选最具体的 |
| 同步 vs 异步 | 导入后**同步跑**（<500 条 batch <2s，自用阶段可接受）；>500 条才提示"后台计算中" |
| 降级开关 | `config.ENABLE_INDICATOR=False` 时跳过指标计算，导入流程不受影响；默认 True |
| 历史数据回填 | 不自动回填历史 2655 条；提供 `scripts/backfill_indicators.py` 手动跑，跑完写 indicator_status |

### 2.6 关键词匹配加词边界（修复 P1-1）

子串匹配改为**词边界匹配**：
- "钢筋" 不匹配 "钢筋混凝土"（"钢筋"后接"混凝土"是材料描述不是钢筋本体）
- "混凝土" 不匹配 "混凝土砖"
- 实现：关键词两侧加 `(?<![一-龥])` 或要求前面是非中文字符/字符串开头

### 2.7 V6 字典版本管理（修复 P1-2）

- `indicator_e_dict` / `indicator_qd_dict` 表加 `version` 字段（如 "V6.1-20260820"）
- 湘标 2.0 出正式版后，导入新字典时：
  - 旧字典标记为 deprecated
  - 已入库的 e_code 保留旧值
  - 提供 `scripts/rebuild_indicators.py` 用新字典重算

### 2.8 2013 清单覆盖（修复 P1-3）

- QD 关键词表保留 2024 清单统计的 TOP10 关键词
- 同时支持 2013 清单：`gb_code_9` 前 4 位在 2013 和 2024 之间基本一致（如 0105 都是混凝土），前缀匹配兜底
- 2013 清单的 item_name 差异通过关键词补充解决（后续根据 unmatched 比例补词）

### 2.9 期货数据现实性（修复 P1-4）

| 项 | 方案 |
|---|---|
| 数据源 | akshare 先试；接口失效时降级为"手动录入信息价"，不阻塞功能 |
| 时间粒度 | 信息价是双月刊，期货是月线——趋势图按季对齐（3 个月一个点），不追求月度精确 |
| 不直接叠线 | 期货线作为**辅助参考**，不在单价图上直接叠加，而是在价格区间旁标注"同期沪铜主力均价 X 元/吨" |
| 水泥 | 无期货，不做期货对比；用衡阳信息价手动录入（双月刊） |

### 2.10 样本口径双 SQL（修复 P1-5）

```
SQL A（样本数，聚合页和明细页必须用同一条）：
  SELECT count(*) FROM boq_item
  WHERE aggregate_id=X AND active=true AND data_source_type='completed'

SQL B（加权均价，分母另算）：
  SELECT sum(unit_rate_num * quantity_num) / sum(quantity_num)
  FROM boq_item
  WHERE aggregate_id=X AND active=true AND data_source_type='completed'
  AND unit_rate_num IS NOT NULL AND quantity_num IS NOT NULL AND quantity_num>0
```

- SQL A 的 count 在聚合页和明细页必须 100% 一致（集成测试断言）
- SQL B 的加权均价是另一个口径，页面标注"按工程量加权"
- 不要求 SQL B 和 SQL A 的行数一致（SQL B 可能因为 quantity_num 为 0 而少几行）

### 任务 2.4　指标计算 Service + 降级开关（1.5 天）

**新文件**：`app/services/indicator_service.py`

```python
def compute_batch_indicators(db: Session, batch_id: int):
    """导入确认后调用（同步，<500条<2s）：
    1. 从内存缓存读 qd_dict/e_dict（启动时加载）
    2. 遍历该 batch active boq_item
    3. 每条调 match_indicator → 回填 e_code/q_code/d_code/indicator_level
    4. 按 e_code 聚合：sum(total_num)，单方造价 = 合价/building_area（如有）
    5. 按 q_code 聚合：sum(quantity_num)，加权单价 = Σ(单价×工程量)/Σ工程量
    6. 结果写回 import_batch.e_summary / qd_summary / indicator_status='done'
    """
```

**降级开关**：`config.ENABLE_INDICATOR = True`，False 时 `import_service` 不调 `compute_batch_indicators`。
