### 任务 1.1　版本识别预处理（1.5 天，P0）

**背景**：现有 2655 条 boq_item 中，unknown 版本占 46%（1220 条）。2013 和 2024 清单编码体系完全不同，同一前缀含义可能冲突，必须先定版本才能准确分类。

**新增文件**：
- `data/version_lookup.py`：从两份 Excel 提取的查表数据（序列化 JSON）
- `scripts/run_version_classify.py`：一次性全量识别脚本
- `tests/test_version_classify.py`：识别逻辑测试

**查表数据来源**：
- 2013 版：`GB50500-2013清单项目_规范提取版_PDF校正.xlsx` → 1710 条 (code, name)
- 2024 版：`GBT50500-2024工程量清单计价.xlsx` → 1617 条 (code, name)

**版本识别 4 层筛选逻辑**：

```
第1层：编码只在某一版独有
  ├─ 命中 2013 独有（584 个 code）→ 判定 2013，confidence=high
  ├─ 命中 2024 独有（491 个 code）→ 判定 2024，confidence=high
  └─ 未命中 → 进入第2层

第2层：编码两版都有，名称完全匹配
  ├─ item_name == 2013 规范名称 → 判定 2013，confidence=high
  ├─ item_name == 2024 规范名称 → 判定 2024，confidence=high
  └─ 未命中 → 进入第3层

第3层：编码两版都有，名称包含匹配
  ├─ item_name 包含 2013 规范名称 → 判定 2013，confidence=medium
  ├─ item_name 包含 2024 规范名称 → 判定 2024，confidence=medium
  └─ 未命中 → 进入第4层

第4层：按编码段倾向 + 项目特征格式兜底
  ├─ 编码段指向 2013 → 判定 2013，confidence=low
  ├─ 编码段指向 2024 → 判定 2024，confidence=low
  └─ 都不指向 → 判定 unknown
```

**两次校验机制**：
- 第 1 次识别：按上述 4 层规则判定
- 第 2 次校验：用交叉规则再验一遍（第 1 层用名称包含验，第 2/3 层用编码段倾向验）
- 两次一致 → 存字段
- 两次不一致 → 存 unknown，标记"待核对"
- 第 1 次 high + 第 2 次 unknown → 存第 1 次结果，confidence=high
- 第 1 次 unknown + 第 2 次 medium → 存第 2 次结果，confidence=low

**预选库流程**：
1. 全量 boq_item 逐条跑 4 层筛选，建临时预选表
2. 预选表做两次交叉校验
3. 校验通过的批量写回 boq_item

**新增字段**：
- `boq_item.item_code_version`：TEXT，"2013" / "2024" / "unknown"
- `boq_item.version_confidence`：TEXT，"high" / "medium" / "low" / "unknown"

**预期效果**：
| 层级 | 预估筛出 | 置信度 |
|---|---|---|
| 第1层：独有编码 | ~1200 条 | high |
| 第2层：名称完全匹配 | ~600 条 | high |
| 第3层：名称包含匹配 | ~500 条 | medium |
| 第4层：编码段倾向 | ~250 条 | low |
| 两次校验不一致 | ~80 条 | unknown |
| 真·unknown | ~25 条 | unknown |

unknown 从 46% 降到 ~4%。

**新导入时自动识别**：import_service 导入完一批，自动跑 4 层筛选，写回字段。

**验收**：
- 全量 2655 条跑完，unknown ≤ 10%
- 抽样 30 条人工核对，准确率 ≥ 95%
- 新导入 10 条测试数据，自动识别正确

```
SQL A（样本数，聚合页和明细页必须用同一条）：
  SELECT count(*) FROM boq_item
  WHERE aggregate_id=X AND active=true AND data_source_type='completed'

SQL B（加权均价，分母另算）：
  SELECT sum(unit_rate_num * quantity_num) / sum(quantity_num)

  WHERE aggregate_id=X AND active=true AND data_source_type='completed'
```

## 四、阶段二：指标集成（第 3 → 7 周，约 7 天）

> 等单价分析做扎实了再启动。第一个交付：导入云溪华庭 → 自动出 E 级 31 个分部单方造价 → 页面能看。

### 4.1 关键设计决策

**指标字段分层**：A 类可重建（e_code/q_code/d_code/indicator_level），不进 B 类保护，写入仍走审计。

**两层聚合键独立**：
| 层 | 聚合键 | 回答 |
|---|---|---|
| 单价层 | aggregate_id（regex:大类:规格） | "YJY-5*10 历史多少钱" |
| 指标层 | e_code / q_code（V6 编码） | "这个工程钢筋含量多少" |

两层不强行映射，导航并列分开。

**E 级回退逻辑**：
```
1. gb_code_9 前4位命中 qd_dict.gb_prefix → QD 分类级
2. item_name 命中 qd_dict.keywords（加词边界）→ QD 分类级
3. 都不命中 → E 级回退（q=d=e_code）
4. 连 e_dict 都没命中 → unmatched
```
预期覆盖率（云溪华庭基线，**待验证**）：QD 级 ~70%、E 级回退 ~15%、unmatched ~15%。

**建筑面积口径**：
- 新导入：导入向导必填 building_area，校验 >0 且 <100 万
- 历史数据：不算单方指标，标注"建筑面积未录入"
- 多栋楼：一个 batch = 一栋楼
- 跨工程对比：过滤无 building_area 的 batch

**降级开关**：`ENABLE_INDICATOR=False` 时跳过指标计算，导入不受影响。
