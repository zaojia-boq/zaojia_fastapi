## 三、阶段一：单价分析做扎实（现在 → 第 2 周，约 4.5 天）

### 任务 1.1　样本口径对齐（1 天，P0）

**改文件**：
- `app/services/page_services.py` get_price_analysis
- `app/templates/portal/price_samples.html`
- `tests/test_price_analysis.py`（新增）

**写死铁律**：
```
SQL A（样本数，聚合页和明细页必须用同一条）：
  SELECT count(*) FROM boq_item
  WHERE aggregate_id=X AND active=true AND data_source_type='completed'

SQL B（加权均价，分母另算）：
  SELECT sum(unit_rate_num * quantity_num) / sum(quantity_num)
  FROM boq_item
  WHERE aggregate_id=X AND active=true AND data_source_type='completed'
  AND unit_rate_num IS NOT NULL AND quantity_num > 0
```

- SQL A 的 count 在聚合页和明细页必须 100% 一致（集成测试断言）
- SQL B 页面标注"按工程量加权"
- 不要求 SQL B 和 SQL A 行数一致（quantity_num=0 会少几行）

**验收**：抽样 20 组，聚合页 count == 明细页 count；测试覆盖。

## 四、阶段二：指标集成（第 3 → 7 周，约 7 天）

> 等单价分析做扎实了再启动。第一个交付：导入云溪华庭 → 自动出 E 级 31 个分部单方造价 → 页面能看。

### 4.1 关键设计决策

**指标字段分层**：A 类可重建（e_code/q_code/d_code/indicator_level），不进 B 类保护，写入仍走审计。

**两层聚合键独立**：
| 层 | 聚合键 | 回答 |
|---|---|---|
| 单价层 | aggregate_id（regex:大类:规格） | "YJY-5*10 历史多少钱" |
| 指标层 | e_code / q_code（V6 编码） | "这个工程钢筋含量多少" |

两层不强行映射，导航并列分开。

**E 级回退逻辑**：
```
1. gb_code_9 前4位命中 qd_dict.gb_prefix → QD 分类级
2. item_name 命中 qd_dict.keywords（加词边界）→ QD 分类级
3. 都不命中 → E 级回退（q=d=e_code）
4. 连 e_dict 都没命中 → unmatched
```
预期覆盖率（云溪华庭基线，**待验证**）：QD 级 ~70%、E 级回退 ~15%、unmatched ~15%。

**建筑面积口径**：
- 新导入：导入向导必填 building_area，校验 >0 且 <100 万
- 历史数据：不算单方指标，标注"建筑面积未录入"
- 多栋楼：一个 batch = 一栋楼
- 跨工程对比：过滤无 building_area 的 batch

**降级开关**：`ENABLE_INDICATOR=False` 时跳过指标计算，导入不受影响。

### 任务 2.1　字典表 + 字段迁移（1 天）

**新模型**：`app/models/indicator_dict.py`（IndicatorEDict 65 个 + IndicatorQdDict 182 个，带 version/deprecated）

**改模型**：
- boq_item 加：e_code / q_code / d_code / indicator_level（4 个 A 类字段）
- import_batch 加：building_area / e_summary / qd_summary / indicator_status

**迁移**：alembic autogenerate；历史数据 indicator_status 回填 `done_legacy`。

**数据导入脚本**：`scripts/import_indicator_dict.py`，读 V6 xlsx 灌入两张表。

### 任务 2.2　指标匹配纯函数（2 天）

**新文件**：`data/indicator_matcher.py`（纯函数，不依赖 SQLAlchemy）

- qd_dict 预编译成 `{gb_prefix: qd_list}` + `{keyword: qd_code}`，O(1) 查前缀
- 关键词匹配加词边界（"钢筋"不匹配"钢筋混凝土"）
- 测试：云溪华庭 496 条重跑，QD 级 ≥65%、unmatched ≤20%（**待验证**）

### 任务 2.3　指标计算 Service（1.5 天）

**新文件**：`app/services/indicator_service.py`

- 导入确认后同步跑（<500 条 <2s）
- 遍历 batch 的 boq_item → match_indicator → 回填编码
- 按 E 聚合：合价 / 单方造价 = 合价/building_area
- 按 QD 聚合：工程量 / 加权单价
- 结果写 e_summary / qd_summary

**改导入向导**：加 building_area 必填字段。

### 任务 2.4　指标查询页（2 天）

**新路由**：`/admin/indicators`、`/admin/indicators/{batch_id}`

**新模板**：`app/templates/admin/indicators.html`
- 工程选择下拉（只列有 building_area 的）
- E 级分部卡片：分部名 + 单方造价 + 占比
- QD 级分类表：分类名 / 工程量 / 单位 / 加权单价
- 点分部卡片看清单明细

**导航**：admin 侧栏加"指标分析"，与"单价分析"并列。

### 任务 2.5　跨工程对比（1 天，有 2 个工程后再做）

- 选 ≥2 个有 building_area 的工程
- E 级分部单方造价并排柱状图

> **注**：当前只有云溪华庭 1 个工程数据，2.5 等真有 2 个工程再做，不提前排期。
